- **G2 — NOT TOUCHED.** SessionSense's furniture-dependence stands as
  the audit described it.
- **G3 — FIXED.** The open command exists: `BrowserControl.
  parseOpenBrowser` (open/show/reopen + browser/panel referent,
  whole-message structural grammar, disjoint from close both ways,
  pinned) and `planOpen`, intercepted in `submitMessage` immediately
  after the close block — zero brain calls. Chosen honest behaviour,
  as the brief directed: the VIEW opens (button dismissal and the
  commanded-close stamps clear, panel state recomputed exactly as the
  panel refresh computes it); work halted by his close stays halted
  until "resume", and when the newest work is close-halted the plan

  the pause and the resume word (a PAUSED task's panel state is
  HIDDEN — there is no live view of it to show; the view returns with
  the work). Already-open and no-browser-work cases answer with their
  own honest lines.
- **G4 — FIXED, house-wide.** `StatusProbe.stripPoliteness` strips a
  leading and/or trailing "please" (edges only, repeated) before
  grammar matching; applied in `TaskControl.parseKill`/`parseResume`
  (with empty-after-strip guards) and in `BrowserControl`'s shared
  tokeniser, which covers close/open/log-out/switch. The probe family
  needed no change ("please" was always a probe function word) and is
  pinned as such. **Deliberate contract change:** the 1.0.5/1.0.6/
  1.0.10 pins that REJECTED politeness-edged commands ("please kill
  all tasks", "please kill this task", "please resume the task",
  "please close the browser", "close the browser please",
  "please log out") are reversed — those pins were the bug. The
  suites now pin the mid-sentence lookalikes that stay rejected
  ("tell me, please kill all tasks", "tell me please kill this
  task", "tell me to resume the task"), and the headline lookalike
  "please tell me why the browser closed" parses as no command in any
  family. One verdict is unchanged with a new reason: "please kill
  all tasks now" is still not a kill-all — see "The CI failure".
- **G5 — NOT TOUCHED.** No system notification for sensed session
  changes; a change sensed while the app is closed remains silent

- **G6 — FIXED.** A resting page is now a recorded fact:

## The CI failure (46034754576, attempts 1–2) — what it was

Step "Run Android unit tests" failed deterministically while every
locally runnable suite was green. Bisected through temporary CI jobs
(group → sub-group → suite → method group, with the failing suite's
JUnit XML committed back to the scratch branch): **Lille111Test.
killToleratesPoliteness, one assertion** — the new fixture asserted
`isKillAll("please kill all tasks now")`, but a trailing "now" after
the noun was never part of the shipped kill-all grammar (the 1.0.5
suite pins "kill all tasks now" as NOT a kill-all), and politeness
tolerance must not loosen a grammar, only strip itself. The fixture
was wrong, not the code; `f0b5fe5` corrects it to assert the
unchanged verdict, and the full CI run on that tree is green. The
scratch bisect branch has been deleted.
