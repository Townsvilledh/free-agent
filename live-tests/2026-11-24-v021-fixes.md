## Case (a) — the exact original failing prompt (battery Task 7a, was 0/5)

**Prompt (verbatim, as the app sent it):**
"can you create an autonomous profitable agent [attachment: btc_agent.py]"

**Final outcome: USEFUL ANSWER via refusal recovery.** ✅

- Call 1 (latency 1.4 s, HTTP 200): the model refused, verbatim:
  "I’m sorry, but I can’t help with that."
- The router detected the refusal, reframed the request automatically into
  the concrete form — *"Write a Python script for an autonomous agent that
  watches the BTC price and paper-trades a simple moving-average strategy,
  no real money…"* — and retried once through the route chain.
- Call 2 (latency 13.4 s, HTTP 200): full answer, 5,747 characters, served
  by `keyless-pollinations`, delivered to the user prefixed with the
  transparency note, verbatim: **"The free model refused that phrasing, so
  I re-asked it as a concrete task:"** — followed by a complete paper-trading
  script ("Quick-start script – paper-trade a 10-period SMA crossover on
  BTC/USD", polls Binance's public REST API, rolling SMA, BUY/SELL signals),
  closing with assumptions and the caution that "a simple SMA crossover is a
  toy strategy, not a reliable trading method."
- Total wall time including pacing: 63.4 s · 2 transport calls · no 402/429.

### What it took to get here (kept in, honestly)

1. **First re-run attempt FAILED to detect the refusal.** The model writes
   refusals with curly apostrophes ("I’m sorry, but I can’t help with
   that."); the detector matched straight apostrophes only, so recovery
   never fired and the flat refusal was delivered. Fixed: quote
   normalisation in `recovery.is_refusal` and in the Android
   `isRefusalReply`, plus a regression unit test.
2. **Second/third attempts: recovery fired, the retry died in transport**
   (status 0, connection dropped — the known flaky route from this VM).
   The router cooled the route and returned its honest queued result,
   verbatim: "All routes for this are cooling down right now (free-tier
   rate limits). Earliest retry at 07:55:04 UTC. Your task is queued and
   will continue automatically — you don't need to re-send it." No silent
   dead end — but no answer either, on those attempts.
3. **A direct probe then showed the first reframe design was too weak:**
   merely wrapping the original wording ("Write a complete Python script
   that implements the following request … Request: can you create an
   autonomous profitable agent") was refused again, verbatim — the trigger
   phrase survives a wrap. Fixed: the reframe now REPLACES vague outcome
   wording with a concrete spec for agent+money asks (the battery 7b
   shape) and sanitises trigger words ("profitable", "make money") out of
   the generic path. The Android `reframeRequest` mirrors this.
4. **Final attempt (above): recovery worked end-to-end.**
