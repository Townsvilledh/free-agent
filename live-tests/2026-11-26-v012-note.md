## 1. Her agentic wallet (WALLET.md)

- **Separate keyset**: generated on-device on an explicit tap;
  the key lives only in her Keystore-wrapped vault, and rides
  the v0.11 encrypted backup via the vault (wiring verified in
  `BackupManager`: seals `vault.exportSecrets()`, restores via
  `importSecrets`). Never in chat/task context or logs; creating
  twice never replaces the key.
- **One agentic wallet, not two**: this IS the Lille-in-Fluid
  spec's companion wallet, connected to the user's Fluid
  identity; Lille is its phone home. The main Fluid wallet is
  never touched — no key, no session method, no code path.
- **Read side**: ETH/USDC/USDT/WETH on Ethereum + Base via
  public RPCs (≥2 routes per chain, serving source named);
  "couldn't load" is a distinct state from a true zero.
- **Prepare-and-ask**: the strict deterministic parser (below)
  or the Wallet screen builds the tx from live state (fees,
  nonce, balances, USD price via CoinGecko → Coinbase →
  Kraken); unpriced sends are labelled and need explicit
  raw-amount confirmation. The approval sheet shows the exact
  send; the Approve tap is the only source of approval.
- **Caps in the signer**: `WalletGate.decide()` runs before any
  key is touched. Defaults $5/tx, $20/day rolling — **the
  user's dial**: raisable to anything or switched off ("no
  limit", one warning line), still enforced deterministically.
  Daily totals persist across restarts. Pinned by JVM tests,
  including a stub signer proving no signature without Allow,
  and the caps-correction tests (raised caps allow what
  defaults refused; caps-off allows any balance-covered amount
  with approval/autonomy rules still applying).
- **Autonomous switch**: settings-only, default OFF. ON =
  within-caps sends skip the sheet, still gated, logged, and
  reported. Never enableable from a prompt.
- **Sweep-back**: send-all to the verified Fluid address,
  always prepare-and-ask, caps-exempt by design.
- **Activity**: created/prepared/refused/sent/confirmed/
  failed/swept, all in her wallet activity list.
- **Zero app-switching**: her wallet's whole life is inside
  Lille; funding (inbound) is the only external step.
- **Exact parser phrasings** (case-insensitive, whole message
  must match, optional trailing "." or "please"):
  `send|pay <amount> <ASSET> to <target> [on <chain>]`;
  `send|pay $<amount> of <ASSET> to <target> [on <chain>]`;
  `send|pay <amount> dollars of <ASSET> to <target> [on
  <chain>]` — ASSET ∈ {ETH, USDC, USDT, WETH}; target = 0x
  address or Fluid name (@name or bare); chain ∈ {ethereum,
  mainnet, base}, default Ethereum. Send-shaped but inexact →
  a question, never a guess.
- Pure-Kotlin EVM stack (no web3 SDK): Keccak-256, secp256k1
  (RFC 6979), EIP-55, RLP, EIP-1559 — pinned by published test
  vectors.

**Honest status**: the money path is test-pinned and shipped,
NOT yet live-proven. The wallet job class becomes "proven"
only when a real send completes on the owner's phone and is
verified by state (BENCHMARK.md register updated to say so).
Task-engine spends are NOT built — chat prompts + Wallet
screen only. EVM only.

## 2. Brain resilience + the exhaustive keyless hunt (ROUTES.md)

Born of a live failure: "hi" → terminal "check your connection"
while his connection was fine. Now: failures are classified
(offline / network / rate-limit / server / permanent);
retryable failures never dead-end — the message stays, an
honest status line names the real cause, the chain falls
through, then retries with escalating waits. "Check your
connection" is only said when the device is really offline
(connectivity is checked first). Per-route health: repeated
failures demote a route (app: 2/10/30-min escalating rests,
skip-while-resting, automatic recovery probe; core: cooldown
×1/×2/×4/×8) until a success clears it.

**The hunt** (Ethuram: "if we can find ten use them all, if 50
use them all"): ~45 candidates got real completion calls in
three rounds on 2026-11-26. **Exactly two routes answer
keyless today — Pollinations and AI Horde — and both are
wired** (Android chat chain + core; Horde is chat-only, skipped
on the tool-call path). Everything else is recorded in
ROUTES.md with its verdict: 28 needs-key, 9 dead/gone, the
"free-ai" trio broken (one shared backend refusing benign
prompts with a junk policy template), duck.ai challenge-walled
(418 ERR_CHALLENGE — browser-minted proofs only; not fought,
per the WALLS.md doctrine), plus shared-fate notes (a long
list would overstate diversity — several services front the
same upstreams).

## 3. Sign where you stand — embedded Fluid sheet

Login pairing no longer requires leaving Lille: "Open Fluid
inside Lille" auto-copies the wc: code and loads Fluid in an
in-app sheet (plain WebView container — no JS bridge, Lille
never reads keystrokes or content inside Fluid; stated in
WALLET.md). Fluid has **no wc: deep link** (checked against
its source: paste-only panel) — PARITY.md records the
Fluid-side `#wc=` follow-up. Caveat stated in-app: the
embedded browser's storage is separate, so a wallet that lives
in Chrome may need creating/importing inside the sheet once.
