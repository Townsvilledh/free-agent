## Part A — full-kit completion

1. **Calendar class.** TaskTools gains CALENDAR (conservative
   detection — calendar/appointment/meeting phrasing; bare
   "remind me" deliberately excluded) and calendar is
   device-AVAILABLE in the plan/declaration logic. On-device
   tools over CalendarContract: `calendar_read` (today /
   tomorrow / week; Instances, so recurring events expand) and
   `calendar_create` (mutating → Plan/Act-gated upstream; the
   created event is recorded and re-read by the finish probe).
   Runtime permission missing → the honest observation naming
   the Android Settings step, never a fake empty calendar.
2. **On-device Gmail.** A separate Gmail connection in
   Settings reuses the app's own Google OAuth stack (Google
   Sign-In + GoogleAuthUtil — the Drive-backup machinery) with
   gmail.readonly. Tools `gmail_list` / `gmail_search` /
   `gmail_read` return only redacted shapes: MailRedact is a
   faithful port of the core's redact.py pattern order (the
   lookahead card pattern documented as omitted on-device);
   the pin holds — a verification-code string's digits appear
   nowhere after redaction. SEND is disabled by default behind
   the core's triple gate (Settings flag → gmail.send scope
   from a second consent → per-send approval parked in the
   chat for "approve send"); the gateway additionally refuses
   while the flag is off (defence in depth). Not connected →
   declared at task start ("one step in Settings connects
   it"), other parts proceed, finish labelled partial.
3. **Lane routing.** REPO_CODE / VIDEO classes ROUTE at run
   start: the v0.4 spec export is written, its receipt
   (`specs/<task id>.json`) is stamped on the record, and the
   chat status + graded report state the hand-off WITH the
   receipt. Pure-code export behaviour intact (NEEDS_RUNNER);
   a mixed job's on-device parts complete and are labelled.
   No terminal "cannot execute" for a routable class.

## Part B — the steals (research §3 numbering)

- **#1 + #6 (OpenClaw) — heartbeat + cron separation.** A
  heartbeat phase joins the proactive pass: over an editable
  HEARTBEAT.md checklist (Settings editor; agent-state store,
  rides the backup) + standing task states. SKIPPED entirely
  when the checklist is empty and the world signature is
  unchanged; SILENT when nothing needs the user; ONE debrief
  report when something does (parked → unreported → due).
  Scheduled work is a separate lane: jobs in the agent-state
  store run isolated (own light task record, recipe tool
  restrictions), with deterministic settle arithmetic —
  success reschedules, failure backs off (interval × 2^n,
  capped at a day), one-shots end, repeated failure surfaces.
- **#2 (DroidRun) — verify-state.** Before any finish is
  accepted, the claimed end state is re-read (note / browser
  resting page vs allowlist / created calendar event / a
  recipe's own check) and the report's success stands on the
  re-read; mismatch names the discrepancy in work terms.
- **#3 (Mobile-Agent) — reflection pass.** Every general
  step is classified deterministically on the record
  (worked / wrong target / no change / unexpected); an
  unmoved page after an action is NO_CHANGE.
- **#4 (DroidRun/AppAgent) — Set-of-Marks.** Pages with no
  element tree carry a numbered 3×4 MARKS grid in the
  formatted state; `browser_click_mark{n}` taps the region
  centre via a real touch pair. Pages with a tree never
  show marks.
- **#5 (Letta/Hermes + Mem0) — tiered memory.** Capped core
  blocks (user / persona / current_goals), explicit memory
  tools, a FROZEN SNAPSHOT stamped on the record at task
  start, a searchable journal underneath, and
  ADD/UPDATE/DELETE/NOOP consolidation on every write.
  Rides the encrypted backup (payload `agentState`).
- **#7 (Hermes) — self-written skills.** A task completing
  after ≥5 tool calls distils a SKILL.md-shaped record;
  matching skills are injected into future tasks; a better
  run patches the skill. Rides the backup.
- **#8 (smolagents) — planning interval + final checks.**
  plan_note owed every 10 browser / 8 note steps (sub-goals
  open/done/dropped, rendered in the expanded status);
  deterministic final checks bounce a finish ONCE with the
  failing check recorded; a second failure finishes honestly
  with the check named in the report.
- **#9 (DroidRun/AppAgent) — per-site cards.** Cheat-sheets
  per domain (key screens, elements, dead-ends), auto-loaded
  for a job's sites, grown from completed runs. Backup.
- **#10 (Goose) — recipes.** User-readable task files:
  typed params with `{{param}}` substitution, a tool
  allowlist enforced at dispatch as a contract, a concrete
  success check feeding verify-state, bounded retries.
  Built-ins: morning-brief, watch-page. Doors: "run recipe
  <name>" in chat; scheduling via the cron lane.
- **#11 (Cline) — Plan/Act + checkpoints.** Consequential
  jobs start in PLAN mode: mutating tools ABSENT from the
  registry and refused at dispatch; propose_plan parks for
  the user's exact-shape approval in chat; approval flips
  to ACT. Every note write checkpoints the prior state;
  "undo last step" in chat restores byte-for-byte.
- **#13 (QVAC) — delegated inference, LAN-first.** "Your
  computer" in Settings: address + model in the vault,
  on/off switch, Test. A user-owned route: leads the own
  routes when enabled + reachable (60 s /models health
  cache in the task lane; the chat lane fails over on the
  call itself), falls back seamlessly. Off by default.
- **#14 (OpenHands) — event log + condenser + stuck.**
  Append-only event log on the record (bounded, condensed
  tombstone event); message context past the bound folds
  into one tombstone message; the stall mechanism is ONE —
  reflection feed + repeated-signature feed → strategy
  change once, then park with a named reason.
- **Honourable mention (AgentScope) — interruption-as-event.**
  A message in a chat whose task is running is recorded as
  a steer and applied at the next step boundary; the run
  is never killed or restarted by a steer.
- **#12 (QVAC model-fit preflight) — DEFERRED WITH REASON**
  (PARITY row 45): Lille has no local-model loading lane
  for a preflight to attach to. Recorded, not built.
