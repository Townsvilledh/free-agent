## What v0.9 built

- **Device lane (Android)** — `BrowserSession` (one persistent
  WebView; its own storage is her on-device session profile),
  driven through the SAME tool contract as the host lane:
  browser_open/read/click/type/type_secret/upload/screenshot/
  wait + vault_gen_secret / vault_record_account + the X lane
  (x_session_status / x_read_feed / x_search / x_post) with the
  same Sentinel gates and copy rules. Perception is structural
  (`BrowserPerception`): DOM via evaluateJavascript, visible
  text + ref-addressed elements, SECRET-field classification,
  presented-only CHALLENGE detection — no vision. Secrets live
  in `DeviceVault` (EncryptedSharedPreferences, Keystore-wrapped
  master key): generated on-device, typed by key name only, the
  value never enters model context, the task record, or any log.
  The tools run in the app's existing durable task runner
  (v0.4 engine): checkpoint after every step, waiting states,
  budget-pause/resume.
- **Lane selection** (`free_agent/lanes.py`, core) — a spec/task
  names `host | device | auto`; auto = device-first for the
  WALLS.md class-A fingerprint-sensitive domains, host
  otherwise; explicit lanes honoured; the choice + reason is
  recorded in the spec report, spec.json, and the device-task
  package. A device-lane spec is packaged by the host core
  (`device_task.json`, STATUS: NEEDS ETHURAM naming the in-app
  step), never faked on the host browser; the app likewise
  exports host-lane tasks instead of running them on-device.
  The X spec now declares `Lane: device`.
- **PARKED_AT_WALL** (WALLS.md build-next #3) — a first-class
  state in BOTH state machines (core `taskstore.py` STATES +
  Android `TaskStates`). A device-lane run that stops at an
  OBSERVED CHALLENGE parks with the wall recorded (domain,
  kind, detail), a screenshot, and the ONE named step. The app
  surfaces a "Lille needs you" card (Tasks screen + notification);
  tapping it opens `BrowserActivity` — her parked WebView,
  full-screen, page state untouched — where Ethuram passes the
  check in her session; "Done — hand back to Lille" resumes the
  task from its checkpoint automatically. Parked tasks are
  never auto-resumed by timers/reboots. Host-lane tasks park
  the same way in the core store (state + report), as v0.8 did.
- **The X retry, packaged** — "Lille: create my X account" on
  the Tasks screen (`XAccountTask`): the v0.8 identity kit and
  hard rules carried in-app, lane=device, mascot avatar as a
  bundled asset, criteria graded from recorded evidence
  (xHandle, firstPostUrl, feed/search evidence) in the in-app
  spec report (Report / Share buttons).
