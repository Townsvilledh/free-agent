## The Fluid login (LOGIN.md)

- Gate is a pure component (FluidGate, JVM-pinned): LOGIN /
  LOGIN_PREFILLED / OPEN exactly as specced; workers
  (TaskWorker, ProactiveWorker, BootReceiver, TaskRunner) have
  ZERO references to the gate — verified by grep; the gate
  guards the UI only.
- Registry: canonical https://fluidwallet.dpdns.org/names.json,
  fallback https://fluidwallet.netlify.app/names.json; fixture
  addresses (ethuram, dripbot, meeday) verified against the
  live registry during the build.
- **ProjectId verdict: Ethuram's existing Reown projectId
  WORKS for dapp pairing.** Evidence: with an SDK-style Ed25519
  did:key JWT, the relay answered HTTP 101 for his projectId
  and 403 for a bogus one; a real pairing URI was generated and
  `irn_subscribe` on its topic returned a subscription id.
  (Bare WS upgrades 401 for every projectId — the relay wants
  the SDK's identity JWT; that is not a rejection.)
- Session requests eip155 only, chain eip155:1 only, method
  personal_sign only. No transaction method exists in the app.
- SDK: com.walletconnect:sign:2.21.0 + android-core:1.23.0
  (the Reown 1.6.x line needs Kotlin 2.4 metadata; this
  project's Kotlin is 1.9.24). The 2.21.0 API was verified from
  the published AARs with javap after the first compile failed
  on assumed signatures: Pairing.create-first connect flow,
  getListOfActiveSessions, sessionTopic-only Disconnect,
  relay.ConnectionType, and NO proposal-expiry callback in the
  delegate (an expired pairing simply never approves; Cancel +
  fresh Connect is the path, and LOGIN.md says so).

- Fresh-user walk done by code/layout audit of every screen
  and control (no emulator/device exists on this VM and local
  Gradle is blocked by the sandbox's loopback policy — stated
  plainly). Fixes shipped: Tasks action buttons toast "Tap a
  task in the list first." instead of silently doing nothing;
  empty Create toasts; BrowserActivity hand-back on a
  non-parked task toasts instead of just closing; SETUP.md
  corrected (the in-app key-vault UI is planned, not shipped).
- Fallback Law on-device: BrainPacing now gates EVERY chat
  brain call (MainActivity was unpaced); honest route census —
  text has exactly ONE keyless route (Pollinations) anywhere in
  the project, so resilience is pacing + escalating cooldown +
  queue/retry and the copy says so; on-device search walks
  three keyless routes (DDG Instant → Wikipedia OpenSearch →
  Open Library) and names the route that served.
- UI polish: ATTACH/SEND are icon buttons (paperclip /
  paper-plane, 48dp, contentDescriptions kept), bubbles +
  pill composer, login card + glossy orange Connect.
- Design fold-in (research 2026-11-26, §6): Direction 1 mascot
  status system (six static drawable states, antenna-dot
  colours; chat header, task rows, login), Direction 2
  mission-log task detail (elapsed / Now / checklist from the
  real trace), Direction 4 debrief sections (Needs you →
  Failed → Finished), Direction 8 honest waiting in chat,
  Direction 5 orange discipline (true-black, tonal surfaces).
  Deferred to v0.11 per Ethuram's note: Autonomy Dial UI,
