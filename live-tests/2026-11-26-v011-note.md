## Item 2 — Autonomous seamless backup: SHIPPED (Drive layer DISABLED-BY-CONFIG)

Design as agreed (BACKUP.md has the full document):

- Key = SHA-256 over a `personal_sign` of the fixed v1
  message, requested through the existing WalletConnect
  session (personal_sign is the session's only method).
  Setup signs TWICE and enables signature mode only when the
  derived keys match; otherwise PBKDF2 passphrase mode, same
  envelope. Key/signature never logged or persisted; key is
  memory-only (`BackupKeyHolder`).
- Payload v1 (AES-256-GCM blob): all chats, task store,
  proactive store, typed settings, identity record, and the
  VAULT contents (decrypted from DeviceVault only at sealing,
  present only inside the encrypted payload). Browser
  sessions OPT-IN (default OFF): CookieManager export for
  x.com / twitter.com / tiktok.com only.
- Layer 1 (automatic): SAF folder grant, sealed blob written
  on change (dirty-flag debounce), on chat-screen pause, and
  via a 12 h WorkManager safety net. Survives uninstall.
- Layer 2 (Google Drive appDataFolder): FULL code path
  (sign-in, find/download/create/update over REST) behind
  `BuildConfig.DRIVE_ENABLED` — **false in this build**,
  because the Google Cloud OAuth client does not exist yet.
  The backup screen says so plainly; nothing fakes a sync.
- Restore: fresh-install discovery (folder + Drive banner),
  one signature/passphrase, integrity + wallet bind check
  (wrong wallet cannot derive the key; the payload's
  username/address must also match the verified identity),
  manual Restore in Settings → Backup & restore, plus file
  export/import escape hatch.
