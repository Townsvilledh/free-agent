## 1. Your own keys door (Settings → "Your API keys (optional)")

- Providers: **Groq, Google Gemini, Cerebras, OpenRouter,
  AgentRouter**, plus one custom OpenAI-compatible endpoint
  (base URL + key, optional model). Per-provider Save / Remove
  / Test — Test makes one minimal `GET /models` call and
  reports only the outcome and a model count; the key is never
  echoed anywhere.
- Keys live **only** in the Keystore-wrapped DeviceVault:
  never plaintext, never in chat/task context, never logged.
  They ride the v0.11 encrypted backup inside the vault —
  never in backup plaintext.
- Route wiring (app chat + task brain): keyless first
  (Pollinations → AI Horde), then Groq → Gemini → Cerebras →
  OpenRouter → AgentRouter → custom, all under the same
  BrainFailure health/demotion machinery as the keyless pair.
  A provider with no key saved is simply absent — no nagging,
  no error. Core parity: the same providers read keys from
  environment variables only.
- The doctrine is unchanged: the app is fully functional with
  zero keys. Keys are the user's own, optional, vault-held —
  nothing is collected, shipped or shared (README, KEYLESS.md,
  ROUTES.md, SETUP.md and PARITY row 29 all say exactly this).

## 2. In-app update check

- The app polls `version.json` on the apk distribution branch
  (the file this release publishes for the first time; the
  build workflow now generates it from build.gradle — the
  version's source of truth — and ships it in the artifact).
- Checked on app open (6-hour throttle) and by the periodic
  proactive pass. A strictly newer versionCode raises a
  dismissible in-app banner (dismissal is per-version) and a
  once-per-version notification; both open the one-tap APK
  link, which installs in place on the stable signing line.
- A failed or malformed check reads as "no update" — silence,
  never an error surface. Compare / throttle / gating logic
  is JVM-pinned (`UpdateCheck`, `UpdateCheckTest`); PARITY
  row 30 records it SHIPPED.

## Honest limits

- No device or emulator exists on this VM: the keys door and
  the update check are JVM-pinned and CI-verified, not yet
  exercised on a phone. The first live proof is Ethuram's
  next open of the app.
- The update check can only announce versions to phones
  already running **0.12.1 or later** — installs on 0.12.0 and
  below hear about this release the old way (the link). From
  this release onward, the app announces its own updates.
- An own-key route is only as live as the user's own key and
  free-tier quota on that provider; the app reports the
  route's health honestly either way.
