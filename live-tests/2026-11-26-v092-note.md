# v0.9.2 — stable signing line (one last uninstall, then never again)

## The problem (evidence, 2026-11-26, Ethuram's phone)

Every Lille update so far had to be preceded by a full uninstall:
Android answered the install-over with an incompatibility error,
and the uninstall wiped her app data. Root cause, confirmed in
`.github/workflows/build-apk.yml`: the workflow signed with "the
standard debug key" — but Actions runners are ephemeral, so each
run generated a **fresh** debug keystore and discarded it. Every
build therefore carried a **different certificate**, and Android
refuses to install a differently-signed build over an installed
app (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`). v0.9.1 included: its
data-preserving resume fix could not be installed over 0.9.0.

## The fix (route a: Actions secret)

1. **One dedicated keystore** created for Lille's builds: RSA 4096,
   PKCS12, alias `lille`, 30-year validity (2026–2056).
2. Stored **only** as GitHub Actions secrets, set through the API
   (repo public key + libsodium sealed-box encryption via the
   custom.github connector helper): `LILLE_KEYSTORE_B64` (base64
   keystore), `LILLE_KEYSTORE_PASSWORD`, `LILLE_KEY_ALIAS`,
   `LILLE_KEY_PASSWORD`. A backup of the keystore + credentials
   sits outside the repo on Ethuram's machine
   (`~/workspace/lille-signing/`, owner-only), so the signing
   identity survives even if the secrets are ever lost.
3. **Workflow**: a restore step decodes the keystore to the
   runner's temp dir (never into the repo) and exports
   `LILLE_KEYSTORE_FILE`; the passwords reach Gradle as env from
   the secrets. The stale "standard debug key" comment is gone.
   When the secret is absent (fork PRs), the step logs the
   fallback plainly.
4. **Gradle** (`android/app/build.gradle`): a `lille`
   signingConfig (PKCS12) applied to the debug build type whenever
   `LILLE_KEYSTORE_FILE` is set; otherwise the default debug key,
   exactly as before. Keystore patterns are gitignored.
5. **SIGNING.md** documents the line, the trade-offs, and the
   fingerprint below.
