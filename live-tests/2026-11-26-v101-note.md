# v1.0.1 (versionCode 24) — seamless fallback + CHAT IS THE ENGINE

One release carrying the whole 2026-11-26 evening direction set,
built on the shipped final tree (main 7c92bfe, versionCode 23):

1. **Seamless fallback (the law).** Route refusals, errors and
   rate-limits are never narrated on any user surface. Fallback is
   immediate: fall-through dispatches the next route at once;
   pacing is per-route (repeat calls to the same route only);
   cooling routes are skipped while another exists. Attribution
   footers stripped from all chat replies (traces only). Refusal
   recovery invisible. All-routes terminal exhaustion shows ONE
   plain line. Stored legacy notes are vetted by NarrationGuard
   before any surface echoes them. Core (router/loop/recovery/
   specmode) mirrors the same discipline.
2. **Status from state.** A bare probe ("update", "how far") in a
   chat with work is answered deterministically from the record —
   no brain call. Lookalikes ("update my bio") are not intercepted.
3. **Chat-output guard.** Every chat reply is screened before
   display (placeholder tokens, self-dialogue; fence-aware). One
   silent regeneration on the next route; a second hit shows one
   plain line and logs the rejected text to the trace only.
4. **Multitasking.** BrainLane: chat never waits behind task brain
   work (wait = 0 by construction); task calls serialise and yield
   after chat. TaskGate: 2 concurrent task runs; the browser lane
   stays exclusive — admission denial retries with the record
   untouched.
5. **CHAT IS THE ENGINE.** The conversation is the workspace:
   in-thread living status line, parked step and graded result in
   the thread, state mark on the chat's list row. The Tasks screen
   is REMOVED entirely (activity, layout, manifest entry); the
   engine/store are untouched. Hand-off wording deleted and pinned
   against.
6. **Visible browser in chat.** Her live WebView session as a
   panel in the conversation while the work browses: watch, take
   over (run pauses), pass the human check in place, hand back
   (WallHandback shared with the browser screen). One plain line
   when another chat holds the lane.
7. **Main page is the main chat.** Quiet tonal header (mascot,
   Chats, New, one menu); the four orange buttons are gone.
   Packaged jobs live in the menu: "Connect my X account" for
   everyone; the owner X action is state-driven and labelled as
   HERS — "Create Lille's X account" until creation is verified
   (task COMPLETED + handle recorded), then "Connect Lille's X
   account". Her password lives only in the vault (x_password);
   the created-state + vault ride the encrypted backup — the
   restore chain is pinned by LilleXStateTest.

Tests: Python suite + new test_chatguard.py (guard detectors,
router regeneration, same-instant fall-through); JVM suites
updated (BrainFailure, BrainPacing, MissionLog, ChatTaskLink)
and new (NarrationGuard, StatusProbe, ChatOutputGuard,
BrainLane, TaskGate, BrowserPanel, ChatWorkMark,
MainChatActions, LilleXState).

Honest limits: no device in this environment — the first
on-device exercise of the chat browser panel, guard
regeneration, multitasking interleavings and the state-driven
X menu is the owner's install walk. The parked X creation task
on his phone carries the legacy title; LilleXState recognises
both titles, so the in-chat action re-adopts it correctly.
