# v1.0.2 (versionCode 25) — TRANSPARENCY + own keys lead + no sleeping while a route lives + watchdog + one sleek menu

One release carrying the whole 2026-11-27 direction set, built on
the shipped 1.0.1 tree (main a0b21a1, versionCode 24). Trigger:
Ethuram's verdict on 1.0.1's in-chat status lines — "I don't know
what she's doing — she's not transparent" — followed the same
morning by the own-keys-lead direction, the no-sleeping hard
requirement, screenshot proof that both live tasks were STUCK
(35+ min unmoved after his Groq key landed), and the menu verdict
("it's off, should be sleek, not like vibecoded stuff").

1. **Transparency — the status renders the record in full.**
   TaskTransparency derives everything deterministically from the
   task record (never a model call): NAMED STEPS from the recorded
   tool calls (web_search → "Searched the web: <gist>", browser →
   "Opened <site>", write_note → "Wrote <file>", a human check →
   "Reached a human check on <site>", failed steps marked "didn't
   work"); a RICH STATUS LINE (short title, last step BY NAME,
   state in work terms, wait reason + "Next try around <time>",
   the parked step naming the user's exact action, last-movement
   time); TAP-TO-EXPAND step list in-thread; ONE living status
   message per task, updated IN PLACE (ChatData.upsertTaskStatus —
   probes refresh it and add at most a "No change since <time>"
   line; twins can no longer stack); graded reports carry the
   named step list above the outcome. Negative pin: no route /
   provider / rate-limit vocabulary in any rendered status or
   report (TaskTransparencyTest).
2. **Own keys lead.** A saved own key walks FIRST in chat, task
   and core routing (Groq → Gemini → Cerebras → OpenRouter →
   AgentRouter → custom), keyless as the fallback; with no keys
   the chain is the keyless pair as always. Order only — privacy
   eligibility is decided before the chain and is unchanged
   (pinned both ways, incl. private content never reaching a
   barred route regardless of order).
3. **No sleeping while a route lives.** A task's rest after an
   all-routes failure is the SHORTEST per-route cooldown
   (BrainPacing.restMs, capped at ~60 s) — never an escalating
   task-level backoff; escalation lives per-route only (per-route
   streaks / rest deadlines / last-call timestamps persisted in
   the record). Pacing floors bind per route only (the ~50 s
   floor is Pollinations-class): a step a healthy route can
   serve proceeds at once, fall-through is in the same breath.
   TaskWorker re-schedules waiting tasks at the record's own
   nextRetryAt instead of WorkManager's escalating retry
   backoff. Saving an own key in Settings wakes every waiting
   task immediately (RouteRestTest pins a–d).
4. **Watchdog — stuck is not resting.** App-open kick: expired
   waits get an immediate pass on app open and every worker
   pass. Stale-wait breaker: a waiting record unmoved >10 min
   is force-retried IGNORING its stored nextRetryAt and all
   pacing state (wait fields cleared at force time). RUN NOW in
   the expanded status view forces a pass for that task. A
   forced pass that still ends waiting records a work-terms
   note on the record, rendered on the status line — a silent
   loop becomes visible state, and the breaker re-arms
   (TaskWatchdogTest). Parked tasks are never touched.
5. **One sleek menu.** Every popup menu renders on ONE shared
   component (LilleMenu): a compact floating tonal card
   (rounded, subtle border, dismiss on outside tap/back),
   reactions as bare emoji glyphs with invisible 44 dp tap
   targets (no boxes/tiles), actions as slim sentence-case
   text rows with hairline dividers (no filled caps bars).
   Applied to the message long-press menu + more-reactions,
   the header ⋯ menu and the chat-list row action. Behaviour
   and plumbing unchanged; style numbers pinned in the pure
   LilleMenuSpec (LilleMenuSpecTest).
